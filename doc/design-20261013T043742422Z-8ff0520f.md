# rs-websocket 配置、TLS 与使用文档修复设计

> 日期：2026-10-13。状态：已接受评审意见后的实施设计。目标版本基于 `qubit-websocket` 0.1.0，允许破坏性 API 变更。

## 目标与依据

本设计解决四项已确认的问题：过大的消息数配置会在建立会话时触发 Tokio 信号量 panic；TLS 默认根证书及自定义根证书的文档与实际语义不一致；帧与消息限额没有说明只作用于入站；中英文 README 缺少完整接入路径，且没有用户指南。现有握手校验、会话关闭、背压和 `qubit-web` 互通行为应保持。

当前实现位置：`src/options.rs` 校验配置，`src/session/queue.rs` 创建信号量，`src/client/handshake.rs` 设置 tungstenite 限额和 TLS connector，`src/session.rs` 创建会话，`tests/` 覆盖配置、协议、会话和互通。`Cargo.toml` 只启用 `tokio-tungstenite` 的 `rustls-tls-webpki-roots`，因此默认根来自打包的 WebPKI 集合，不来自操作系统。传入 `RootCertStore` 时，当前 connector 只使用该 store。现有公开字段 `max_frame_bytes` 和 `max_message_bytes` 实际通过 tungstenite 约束入站读取；出站只由 `outbound_bytes` 限制。

## 方案决策

### 1. 在建客户端时完整验证队列容量

`WsClientOptions::validate()` 同时检查 `inbound_messages` 与 `outbound_messages` 不超过 `tokio::sync::Semaphore::MAX_PERMITS`。保留现有非零、字节信号量和大小关系检查。任何超限均由 `WsClientBuilder::build()` 返回 `WsErrorKind::InvalidConfig`，而不是在连接成功后 panic。`BoundedQueue::new()` 的断言保留为内部不变量保护；不把内部构造器暴露为公共 API。

消息数上限采用 Tokio 当前公开常量，不复制其数值。由于测试无需分配该数量的消息，只验证 `MAX_PERMITS + 1` 被拒绝和 `MAX_PERMITS` 通过配置校验；后者不实际创建连接。

### 2. 固定 TLS 信任根契约

默认使用 WebPKI 根证书，继续校验证书链与主机名。将 `root_certificates(RootCertStore)` 定义为**追加信任根**：连接时构造 WebPKI 默认根集合，再加入调用方提供的根。项目直接声明与 rustls 0.23 兼容的 `webpki-roots` 依赖，不依赖转移依赖来访问默认集合。默认和追加根走同一条显式 rustls connector 路径，避免因是否传入自定义根而切换信任策略。`None` 表示只使用 WebPKI 根；空的自定义 store 与 `None` 等效。重复的根证书由 rustls 的根证书集合语义处理，不在本 crate 另造去重逻辑。

这项变更扩大使用自定义根时的信任范围：原先调用方可通过传入 store 实现“只信任这些根”，变更后仍信任公开 WebPKI 根。由于用户允许破坏性变更，保留明确的安全选择：新增 `exclusive_root_certificates(RootCertStore)`，表示**替换**默认集合。Builder 用内部互斥枚举保存 `Default`、`Additional`、`Exclusive` 三种模式；最后一次根证书配置调用决定模式。`WsClientOptions` 目前为公开结构体，因此同样以公开 `WsTrustRoots` 枚举表示这三种模式，替换原 `root_certificates: Option<RootCertStore>` 字段；默认值为 `WsTrustRoots::Default`，并从 crate 根导出。Builder 的 `root_certificates` 保持名称并设置 `Additional`；新方法设置 `Exclusive`。文档必须说明 `Exclusive` 中的空集合会导致所有 WSS 证书校验失败，不提供跳过验证选项。

测试用本地测试 CA 验证追加和独占的区别：追加模式接受测试 CA 签发的端点，独占模式也接受该端点；通过检查构造出的 trust store 含有 WebPKI 根且独占模式不含 WebPKI 根来验证默认根是否保留，不依赖公网。证书与主机名验证的现有负例继续通过。

### 3. 明确限额方向，保留现有出站语义

将公开字段破坏性重命名为 `max_inbound_frame_bytes` 和 `max_inbound_message_bytes`。它们只约束从对端读到的单帧及重组消息；对应 `FrameTooLarge`、`MessageTooLarge` 是入站读取错误。`outbound_bytes` 同时是出站队列总 payload 预算与单条待发送消息的最大 payload 长度；`outbound_messages` 限制队列消息数。出站帧不由入站字段约束，也不由本 crate 自动分片。这样不会在升级时意外缩小现有发送能力。若调用方要符合对端帧/消息上限，由调用方按照对端协议选择 payload 大小。

校验仍要求 `max_inbound_frame_bytes <= max_inbound_message_bytes <= inbound_bytes`，但移除入站消息大小必须小于 `outbound_bytes` 的无关耦合。tungstenite `WebSocketConfig` 读取新字段；出站 `max_write_buffer_size` 仍按 `outbound_bytes + 14` 计算并检查溢出。所有代码、示例、测试、Rustdoc、README 和指南使用新字段名。新增测试固定：出站 payload 大于入站帧或消息上限但不超过 `outbound_bytes` 时可入队；超过 `outbound_bytes` 时返回 `WsSendError::MessageTooLarge`。入站超限的现有协议测试继续验证错误分类。

### 4. 为两种语言补齐接入与排障路径

`README.md` 和 `README.zh_CN.md` 保留项目定位、六枚徽章、限制与既有尾部结构；在功能简介后加入安装和完整最小调用链。以“服务连接一个由应用提供的回显/事件 WebSocket 端点”为同一场景：给出启动前提、`WsClient::builder().build()`、`connect`、`send`、`receive` 的成功/终态分支、`close`，并指向仓库中的 `ws_client` 示例。代码只使用公开 API，不把入队成功写成对端处理成功。

新建 `doc/user_guide.md` 与 `doc/user_guide.zh_CN.md`。两版都沿同一场景依次解释准备和 WSS 信任根、连接与鉴权头、子协议、接收循环与 `WsSender` 并发发送、双限额背压、入站超限和慢消费者、正常关闭/异常终态、取消与重试责任。每项重要能力写明触发条件、配置、可观察结果和应用后续动作；排障表按症状定位 `WsErrorKind` 与 `WsSendError`。提供语言互链、README、API 文档及可运行示例链接。设计文档 `doc/design.zh_CN.md` 保留为首版历史设计，新增设计为本轮行为变更权威说明；需要时在历史设计开头加指向本文的“当前行为”提示，避免读者依赖过时字段。

## 非目标与边界

本轮不增加代理、压缩、重连、业务 ACK、服务端或平台系统根证书模式；不修改 `rs-web` 的生产代码。现有 `rs-web` 只作为本仓库互通测试依赖，未发现生产下游使用 `qubit-websocket`，因此没有跨仓库迁移任务。破坏性字段变更须在版本说明或 README 的迁移提示中列出旧名与新名；是否提升 crate 版本由后续发布流程决定，本计划不发布。

## 验收标准

1. 所有无效容量在 `build()` 阶段返回 `InvalidConfig`；建立会话不因公开配置超限而 panic。
2. 默认 WebPKI、追加根、独占根三种模式在代码、Rustdoc、README、指南和本地 TLS 测试中一致，证书与主机名校验不被关闭。
3. 入站字段名和出站预算的方向在公开 API 与测试中一致；旧字段名完全移除。
4. 中英文 README 包含完整最小调用链；两份指南可从 README 到达，链接、示例、术语、失败边界相互对应。
5. `cargo test --locked`、`cargo clippy --locked --all-targets -- -D warnings`、项目 rustfmt 配置检查、`cargo doc --no-deps --locked` 通过；最终 Git diff 仅包含本轮实施范围。
