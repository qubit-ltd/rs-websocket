## WS-A01：移除注册阶段的重复扫描

`QueueInner::register_waiter` 现在只在 state 锁内插入 waiter 并返回 guard，不再立刻运行容量 waiter 选择器。容量释放和 waiter handoff 仍运行原有选择逻辑；`push_recoverable` 注册后仍 enable 通知并重试入队。释放/登记在同一 state 锁下串行化：若容量先释放，注册后的重试会观察空位；若 waiter 先登记，释放路径会选择它。关闭广播、取消交接和 RAII 预算回收未改变。

新增零长度消息竞争回归，覆盖 byte budget 已耗尽时零长度消息直接入队、释放消息槽后非空 waiter 继续前进、FIFO 与 usage 清零。原实现和候选均通过该行为回归。

相同 Rust 1.94.0 release 构建、Linux 环境、payload、128-byte budget、计时范围和七轮采样下，byte-limited registration p50 从 4,096 waiter 的 34.81 ms 降至 1.65 ms，从 16,384 waiter 的 638.94 ms 降至 7.33 ms。结果超过本轮新设 30% 目标；count-limited、zero-byte fast path、普通 Text/Bytes push/pop 和 wake 对照未见稳定退化。双 worker 16k cancel p50 有约 8.9% 波动和两轮高尾，完整限制见 evidence，未将压力结果当作业务 SLA。
