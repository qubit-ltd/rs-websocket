# 架构说明

本文说明 `qubit-websocket` 0.1 的现行结构。也可阅读 [English version](architecture.md)。[关闭协调设计](design-20261014T021031598Z-49c7bedd.md)是已经实施的历史记录；[本轮请求头与背压设计](design-20261014T043823504Z-0ceb2c88.md)记录了已完成的修复。当前行为以源码和 API 文档为准。

## 分层与职责

客户端与握手层校验端点和请求选项，建立传输连接并完成 HTTP/1.1 WebSocket 升级。握手成功后创建 `WsSession`；若失败，会在会话创建前返回 `WsError`。TLS 信任策略和请求头由应用通过 client builder 配置。

IPv6 URL 字面量必须带方括号，例如 `ws://[::1]:8080/events`。握手解析器只在生成 TCP 目标时去掉方括号，并校验其中的 IPv6 地址；带作用域标识的 IPv6 地址不受支持。WSS 仍会校验证书链和服务端身份。

会话 API 为应用提供接收接口和发送端。入站、出站队列都受消息数量和 payload 字节数限制。`send()` 等待队列容量，`try_send()` 立即报告容量情况；队列无法接纳消息时，两者都返回 `WsSendError`。关闭状态优先：观察到队列关闭后发送会返回 `Closed`，即使消息超限也一样；只有队列仍开放时，超限消息才返回 `MessageTooLarge`。消息成功入队不代表已经送达或得到业务确认。

出站 payload 队列预算与 WebSocket 驱动的写缓冲上限是两项独立限制。写缓冲额外增加 14 字节以容纳最大数据帧头，并增加 131 字节以容纳最大客户端控制帧，因此最小有效 payload 预算下仍能处理 Ping/Pong/Close。这两项预算都不是整个会话精确的内存上限；如果传输 I/O 无法继续，预留空间也不能保证对端收到帧。

`WsSession` 持有接收权和会话存活权。释放它会同步请求驱动执行有界本地关闭，并关闭两侧队列；仍被克隆持有的 `WsSender` 会因发送队列关闭而返回 `WsSendError::Closed`，不能延长会话寿命。已入队但尚未写出的消息可能被丢弃。Drop 不等待关闭握手，因此不能据此观察对端是否确认；要取得关闭结果，应用必须显式调用 `close().await`。

会话驱动负责协议 I/O，并协调读写任务。它处理 Ping、Pong 和 Close 控制帧，将文本与二进制消息交给应用。关闭协调会停止接纳新的业务消息，尝试回复协议 Close，并在配置的关闭期限内等待结束。驱动记录单一终态，应用可通过 `termination()` 查询。

入站队列满时，驱动最多暂存当前等待入队的一条消息，同时继续轮询控制帧。若随后又收到业务数据，会立即进入慢消费者关闭路径；若没有额外业务数据，则由 `no_progress_timeout` 限制等待时间。驱动会尝试发送 `1013` Close，但写入失败时无法保证对端收到。此路径的 `Timeout` 是会话故障分类，不表示业务处理完成，也不表示对端已确认关闭。

## 结果边界

| 结果 | 含义 | 应用职责 |
| --- | --- | --- |
| `WsSendError` | 出站消息未能进入会话队列。 | 决定等待、延后、拒绝请求或停止生产。 |
| `WsTermination::Closed { code }` | WebSocket 关闭握手已完成；若对端提供状态码，则原样保留。 | 按应用协议解释状态码。`1009` 不代表业务成功。 |
| `WsTermination::Error { kind }` | 关闭协调或其他终止操作失败，会话以错误结束。 | 诊断并选择恢复策略；库不会自动重连或重放消息。 |
| `receive()` 或 `close()` 返回的 `WsError` | 会话级操作报告故障；终态接收错误只交付一次。 | 处理错误，并确认停机结果。 |

`WsErrorKind::Transport` 覆盖连接建立、运行期传输 I/O，以及 HTTP 升级期间的普通网络 I/O；HTTP 拒绝或结构化升级校验失败归为 `WsErrorKind::Handshake`。TLS 错误仍单独归类。驱动任务故障归为 `WsErrorKind::Internal`。发送队列接纳失败属于 `WsSendError`，不会仅因一次发送失败就变成会话终态错误。

## 停机流程

优雅停机时，服务先停止生产者，再通知 worker 并等待它结束。worker 停止消费后调用 `close().await`，并检查终态。关闭握手受配置的超时限制；若对端未及时完成，停机操作会返回超时或已记录的终态错误。需要确认关闭结果时，应显式等待关闭流程，不能用丢弃会话代替。

事件解码、持久化、业务确认和断线恢复均由应用负责。尤其是，协议关闭完成不能证明队列中的命令已被处理，也不能证明已消费事件已持久化。
