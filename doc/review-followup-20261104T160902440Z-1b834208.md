## WS-R01：容量充足时快速入队

`BoundedQueue::push_recoverable` 在登记 waiter 前先调用 `try_enqueue`。立即接纳时通知 reader 并返回；关闭时返回原 `WsMessage` 与 `Closed`；容量不足时仍登记 waiter，并保留 enable 通知后的第二次接纳尝试。

`test_queued_fast_path_does_not_register_waiter` 与 `test_queued_fast_path_closed_queue_returns_message_without_registration` 通过私有 `next_waiter_id` 验证两条直接路径不登记 waiter，同时核对消息所有权及预算释放。TDD 红阶段命令 `cargo test --locked --lib queued_fast_path` 因两条断言均观察到 waiter ID 从 0 增至 1 而退出 101；加入快速路径后同命令退出 0（2 passed）。

release 探针使用预构造 Text/Bytes 消息循环移动，预热 10,000 次后各 7 轮 100,000 次异步 push/pop/释放。基线 Text/Bytes 中位数为 345/343 ns/op；快速路径后为 169/168 ns/op，最终候选为 167/168 ns/op。原始输出在 `queue-followup-baseline-reused-payload.log`、`queue-followup-fast-path.log` 与 `queue-followup-optimized-final.log`。既有 `wake_probe` 在 1/16/128 个等待者、均匀/混合负载下通过；低竞争 p50 没有稳定退化超过 10%。单等待者及尾延迟样本较少且存在微秒级调度噪声，不能据此声称小样本尾延迟改善。

## WS-R03：取消与关闭测量及条件优化

基线探针经首次 poll 确认 waiter Pending，测量 128/1024/4096/16384 waiter、均匀与混合 payload、7 轮集中取消、关闭与 drain、部分取消后的单个进展位及预算回收。current_thread 取消期间由独立 OS 线程观察 1 ms heartbeat 并提供 30 s 看门狗；另以两个 worker 补测取消和 heartbeat。多线程补测只覆盖取消，不重复 close/drain 和部分取消；它不是产品 SLA。

4096 waiter 基线达到计划定义的优化触发条件：current_thread 均匀取消 7/7 轮中位数 13.33 ms；混合取消 7/7 轮中位数 21.65 ms，heartbeat 最大间隔中位数 23.80 ms。两个 worker 的 4096 waiter 取消中位数为 13.29 ms，heartbeat 间隔约 2.07 ms，显示另一个 worker 仍可调度 heartbeat。环境与完整逐轮数据分别在 `baseline-environment.txt`、`summary.txt`、`queue-followup-baseline-reused-payload.log` 和 `queue-followup-multithread-baseline.log`。

先行的 `BTreeMap` 候选虽然显著改善均匀取消，却使 4096 混合取消达到约 33–41 ms。数据表明删除未选中的 waiter 后仍全量重扫集合；同时 close 后逐次广播也带来重复工作。候选据此修正为：使用 `BTreeMap<usize, Waiter>` 按 ID 删除/重置并按 ID 顺序选择；仅在被移除或重置 waiter 曾被选中时重新选择；close 状态转换在同一锁内通知所有已有 waiter，closed 后的删除/重置/预算释放不再广播。关闭后的新 push 会在登记后的第二次接纳检查中立即观察 `Closed`。

修正候选在相同 4096 配置下 current_thread 均匀取消中位数为 2.13 ms，混合取消为 0.95 ms；对应 heartbeat 间隔中位数分别为 4.26 ms、3.06 ms。多线程取消中位数降为 2.13 ms。4096 waiter close 后 drain 中位数从 147.13 ms 降至 1.10 ms。16384 waiter 均匀/混合取消中位数从 378/488 ms 降至 4.06/4.65 ms，close 后 drain 从 1.82 s 降至 4.41 ms。各组每轮预算均归零，所有 close waiter 均观察 `Closed`，部分取消后恰好一个 waiter 前进。最终候选超过设计要求的 30% 收益且正常/低竞争路径没有稳定超过 10% 退化，因此保留；首次候选已由上述扫描修正取代。

完整前后日志：`queue-followup-baseline-reused-payload.log`、`queue-followup-optimized.log`（保留首次候选退化诊断）、`queue-followup-optimized-final.log`。`wake-probe-optimized.log` 与 `wake-probe-optimized-repeat.log` 均退出 0；128 waiter 的最终重复测量与基线 p50 为 2/1/1/1 μs，整体耗时均为 5–6 ms，未观察到稳定低竞争回退。
