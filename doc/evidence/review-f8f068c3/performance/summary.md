## WS-R02：128/129 阈值抖动

每批保留 N 个真实 pending waiter，队列消息和字节预算均被一个占位消息占满；测量 64 次对新第 N+1 个 waiter 首次 poll 并取消，分别累计首次 poll、取消平均耗时及完整 64 次周期耗时。N 顺序按轮次轮换：16、64、128、129、256、1024。129 个基准 waiter 时索引已启用，额外 waiter 的加入/取消不会跨越阈值。

| 常驻 waiter N | 第 1 轮周期 p50 | 第 2 轮周期 p50 | 第 3 轮周期 p50 | 首次 poll p50 范围 | 取消 p50 范围 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 16 | 50.4 µs | 34.6 µs | 54.4 µs | 288–409 ns | 174–294 ns |
| 64 | 53.7 µs | 35.7 µs | 56.9 µs | 299–436 ns | 180–305 ns |
| 128 | 381.7 µs | 388.2 µs | 395.5 µs | 5.08–5.31 µs | 761–794 ns |
| 129 | 41.8 µs | 41.0 µs | 53.7 µs | 338–427 ns | 225–300 ns |
| 256 | 52.2 µs | 48.6 µs | 64.4 µs | 395–506 ns | 285–391 ns |
| 1024 | 42.7 µs | 42.4 µs | 43.4 µs | 346–349 ns | 234–248 ns |

在 128 个基准 waiter 的场景，加入第 129 个时会构造索引，取消后又退回 128 并清理索引。三轮中完整周期中位数约为 0.38–0.40 ms/64 次，而 129 个基准 waiter 时约为 0.041–0.054 ms/64 次；首次 poll 中位数也稳定高出约一个数量级。这和跨阈值构建/销毁索引的成本相符，复现了 WS-R02。2-worker 独立队列竞争补充为 0.378 ms/64 次（p50），但该竞争任务不争用同一队列锁，不能代表多个生产者在同一队列上的争用。

T3 可评估保留当前启用阈值 128、将停用阈值降到 64 的滞回候选；先加 128/129 往返、回落到 64 及解锁后清理语义回归，再做候选对比。索引在 65–128 waiter 时会继续驻留，额外内存有界于该小集合的索引节点；本轮未测量字节级内存代价。当前样本只说明切换成本明显，不能证明滞回对其他队列路径无退化。

## WS-R03：payload 大小多样性

每个批次预先分配 1..K 字节文本、构建并 poll K 个 pending future；队列 `max_messages=2` 且两个消息占满 count/byte 预算。选路计时只包含释放一个 reservation。每个 waiter 使用独立 `WakeCounter`；释放后断言最老可容纳 waiter 被选中，0% 场景断言没有 waiter 被误唤醒。`quarter` 对 K=1 受整数粒度限制，实际 eligible 为 1/1；其他 K 的实际比例为 25%。

| K | eligible 目标/实际 | 第 1 轮释放 p50 / p95 | 第 2 轮释放 p50 / p95 | 第 3 轮释放 p50 / p95 |
| ---: | --- | ---: | ---: | ---: |
| 128 | 0% / 0 | 579 / 616 ns | 515 / 566 ns | 474 / 517 ns |
| 128 | 25% / 32 | 186 / 209 ns | 196 / 262 ns | 191 / 211 ns |
| 128 | 100% / 128 | 186 / 232 ns | 192 / 293 ns | 196 / 222 ns |
| 1024 | 0% / 0 | 186 / 215 ns | 164 / 209 ns | 226 / 304 ns |
| 1024 | 25% / 256 | 3.15 / 3.37 µs | 3.15 / 3.80 µs | 3.22 / 3.42 µs |
| 1024 | 100% / 1024 | 9.87 / 10.17 µs | 9.90 / 10.37 µs | 9.95 / 14.42 µs |
| 4096 | 0% / 0 | 254 / 366 ns | 261 / 355 ns | 768 / 1.54 µs |
| 4096 | 25% / 1024 | 10.91 / 11.54 µs | 10.76 / 11.43 µs | 16.56 / 32.25 µs |
| 4096 | 100% / 4096 | 35.51 / 119.86 µs | 34.88 / 42.66 µs | 35.80 / 51.11 µs |

K=1、16 的三种场景大体在 0.1–0.25 µs，K=128 的可容纳场景也约 0.2 µs。索引启用后，选路时间随 eligible 大小 bucket 数明显上升：K=1024 的 25%/100% 分别约 3.1/9.9 µs；K=4096 的前两轮约 10.8–10.9/34.9–35.5 µs。0 eligible 时只需判断没有 bucket 可选，通常低于 0.8 µs。测量支持“可容纳 bucket 扫描会主导高 K 释放延迟”的解释；K=4096 第三轮 quarter 的 p50/p95 上升，显示主机干扰不可忽略。

T3 可评估设计中的最小快路径：若全局最老的未通知 waiter 已可容纳，则直接选择它；否则沿用 bucket 扫描。当前合成序列的最老 waiter 总能容纳，因此候选预期主要改善 25% 和 100% 场景。候选必须以相同 FIFO/eligible 选择回归覆盖，并按 T3 的 20% 收益、三轮同向及控制场景不超过 10% 退化标准复测。此次结果不能单独确立应保留优化。

## T3 基线/候选交错比较

按外层三轮交替运行基线与候选：每轮先运行阈值、payload 基线探针，再运行对应候选；每次探针仍包含 3 个内部交错轮次、每场景 3 批预热和 30 个测量批次。每个外层版本的 3 次调用因此各提供 9 个场景 p50，以下报告 9 个汇总 p50 的中位数。所有命令均退出 0。

| R02 首次 poll，常驻 128 waiter | 5.335 µs | 415 ns | -92.2% | 三轮一致 |
| R02 控制：常驻 16 waiter 周期 | 33.444 µs | 33.191 µs | -0.8% | 未见稳定退化 |
| R02 控制：常驻 64 waiter 周期 | 34.202 µs | 34.056 µs | -0.4% | 未见稳定退化 |
| R02 控制：常驻 129 waiter 周期 | 39.906 µs | 39.519 µs | -1.0% | 未见稳定退化 |

候选 v1 曾在 0% 场景无条件读取最老 waiter；K=4096 中位数一度比基线高约 34%。该版本未保留。候选 v2 将快路径限制为索引已激活且存在空闲字节的场景，空闲字节为零时跳过额外查找；并仅在 waiter 数超过 128 时检查最老未通知 waiter。该限定不改变 65..128 的小集合扫描，也不触碰未激活索引路径。v2 的 4096/0% 中位数仅高 9.7%，配对方向不一致且各轮样本受主机干扰，未观察到稳定超过 10% 的退化。R03 的 4096/25% 与 100% 三轮均改善超过 20%。因此保留此最小候选。

R02 滞回使索引在 65..128 waiter 时继续驻留，最多为这一有限集合保留索引节点；本轮没有可靠的字节级内存测量。源码仍在低水位 64 及以下释放索引，并保持解锁后析构。没有为快路径新增树结构或依赖。

基线和候选探针日志按 `compare-baseline-{1,2,3}-*.txt`、`compare-candidate-{1,2,3}-*.txt` 命名；R03 候选 v2 对比保存在 `compare-*-v2-{1,2,3}-payload.txt`。第一个 R03 候选及其控制结果也保留，用于说明为什么增加空闲字节条件。
