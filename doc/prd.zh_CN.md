# rs-websocket 产品需求文档

> 版本：首版需求基线；日期：2026-10-11；状态：首版实现。

## 1. 背景与定位

`rs-http` 的 `qubit-http` 面向 HTTP 请求/响应，并在响应流上解码 SSE；`rs-web` 的 `qubit-web` 提供 WebSocket 服务端升级与会话管理。Rust 服务若要主动连接其他 WebSocket 服务，目前需要自行处理连接、认证请求头、`wss://`、限额、收发背压、控制帧、取消和关闭。重复实现这些传输职责容易造成资源约束与错误语义不一致。

`rs-websocket` 是独立的客户端仓库，Cargo 包名为 `qubit-websocket`。它面向使用 Tokio 的 Rust 服务；与 `qubit-web` 在协议层互通，但不依赖服务端 crate，也不要求使用 `qubit-http`。传输库不理解业务命令、JSON-RPC、事件 ID 或业务确认。

## 2. 目标用户与场景

主要用户是需要作为 WebSocket 客户端的 Rust 服务开发者。例如，一个服务连接 `qubit-web` 的受保护端点，发送任务命令，持续接收进度和结果；调用方在部署停止时取消连接，并区分认证失败、握手失败、传输断开与正常关闭。

首版的成功标准是：调用方能在一个连接对象上配置握手、资源限制和关闭策略；长期连接不会因为默认无限队列而无界增长；连接结束时能观察原因并释放任务。连接建立成功不表示业务命令已被接收，消息入队成功也不表示对端已处理。

## 3. 首版范围（P0）

| 编号 | 需求 | 可验收结果 |
| --- | --- | --- |
| P0-01 | 使用 `ws://` 和 `wss://` URL 连接，`wss://` 默认验证服务器证书与主机名。 | 本地 WS/WSS 服务连接成功；无效证书或主机名被拒绝。 |
| P0-02 | 支持调用方设置握手请求头与可选的子协议列表。 | 服务端能收到认证请求头；只接受服务器从提议列表中选定的子协议；不输出敏感头值。 |
| P0-03 | 校验服务端握手，拒绝非 `101`、错误 `Upgrade`/`Connection`、错误 `Sec-WebSocket-Accept` 和不合法的子协议响应。 | 每类错误返回可区分的握手错误；不会把失败响应当作已建立会话。 |
| P0-04 | 为连接、握手、帧、重组消息、入站与出站缓冲及关闭等待设置有限上界。 | 非法零值在建客户端时失败；达到限额时返回确定的错误或关闭原因，内存不会随消息数无限增长。 |
| P0-05 | 支持文本、二进制消息收发，处理 Ping、Pong、Close 控制帧。 | 与 `qubit-web` 的 `ws` 路由双向互通；读取循环持续驱动控制帧处理。 |
| P0-06 | `try_send` 立即报告背压，`send` 在容量可用前等待且受取消影响；两者不承诺网络送达。 | 队列满时 `try_send` 返回 `Backpressure`；等待中的 `send` 在取消或关闭后结束。 |
| P0-07 | 支持显式关闭和取消，关闭等待有截止时间，所有后台任务最终退出。 | 正常关闭发送 Close 并等待响应；超时后释放连接；不会遗留读写任务。 |
| P0-08 | 提供结构化连接、握手、协议、限额、超时、取消与关闭错误；诊断默认脱敏。 | 错误可按类别匹配；URL 凭据、token 请求头和消息内容不出现在默认 `Debug`/`Display` 中。本 crate 不集成 tracing，因此 trace 验收不适用。 |

## 4. 后续范围（P1）

- **显式自动重连：** 可配置退避、最大尝试或总时长，并在每次新连接上重新生成认证材料。断线后不得默认重放业务消息；调用方负责幂等键、游标和补偿。
- **代理与自定义传输：** 在明确 HTTP CONNECT、SOCKS、TLS 证书及 DNS 行为后加入。首版仅使用直接 TCP/WSS 连接，不声称继承 `qubit-http` 的代理、重定向或连接池设置。
- **可选压缩：** 仅在有独立的解压后消息限额、资源预算和协商测试时考虑 `permessage-deflate`。

## 5. 明确边界

- 首版只实现 RFC 6455 的 HTTP/1.1 WebSocket 握手，不实现 HTTP/2 扩展 CONNECT、HTTP/3 WebSocket、浏览器运行环境或服务端监听。
- 不自动跟随握手重定向；目标变更可能泄露认证头，应由调用方显式决定新的 URL 和凭据。
- 不把 Origin 作为认证；调用方可按服务端要求设置 Origin，身份验证仍由服务端策略负责。
- 不实现业务消息的持久化、确认、重放、顺序恢复或恰好一次交付。
- 不要求 `rs-http` 或 `rs-web` 修改其公开 API；互通测试可将 `qubit-web` 作为测试依赖或启动测试服务。

## 6. 验收场景

1. **连接与鉴权：** 客户端携带 bearer token 连接 `qubit-web` 受保护路由，发送文本并收到响应；错误 token 返回握手拒绝，诊断中不含 token。
2. **双向流量：** 服务器在客户端持续发送时仍可主动推送消息；Ping/Pong 在应用正常消费消息期间得到处理。
3. **容量：** 使用很小的出站消息数和字节上限，暂停服务端读取后触发背压；入站消费者暂停后达到入站上限，不允许无限排队。
4. **边界输入：** 超大帧、超大重组消息、非法握手、未提议的子协议、无效证书分别产生可分类结果。
5. **生命周期：** 客户端主动关闭、对端先关闭、网络突然断开、连接超时、取消和关闭超时均使会话结束，任务与容量被释放。

## 7. 交付与度量

首版交付物包括 crate 源码、公开 API 文档、WS/WSS 示例，以及覆盖上述验收场景的本地集成测试。发布前运行项目 CI、`cargo test --locked`、`cargo doc --no-deps --locked` 和与 `qubit-web` 的互通测试。本次实施的各项测试和 CI 结果记录在实施计划的执行记录中；本项目尚未在本次任务中发布到 crates.io。
