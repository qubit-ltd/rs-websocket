# rs-websocket 关闭协调与文档边界修复设计

> 日期：2026-10-14。目标版本：`qubit-websocket` 0.1.0。本文件是待实施方案；当前行为仍以源码为准。用户已接受本轮全部评审意见，并允许必要的破坏性变更，无需另行审批。

## 目标与依据

本轮保持 WebSocket 客户端、有界队列、TLS、握手和应用自行恢复的既有定位，修复关闭结果可能失真的并发路径，完善发送错误的标准 Rust 错误接口，并让测试与文档反映真实模块边界。`rs-web` 仅作为本仓库的互操作测试服务端；当前未发现其他 `rs-*` 生产代码直接依赖本 crate。

评审时 `cargo test --locked` 的 36 个单元测试、46 个集成测试、11 个 doctest 均通过，项目样式检查也通过。这说明现有用例没有覆盖下述调度窗口，不能证明窗口不存在。

## 现状、根因与必须维持的不变量

### 本地主动关闭的假成功窗口

`WsSession::close()` 当前先调用 `outbound.close()`，再向 `watch` 通道发送 `CloseRequest::Local`。队列关闭会唤醒 `write_loop` 的 `outbound.pop()`；若写任务在两步之间运行，`outgoing?` 会直接返回 `None`。`run_parts` 的“写任务先结束”分支把这个 `None` 与 `ReadResult::LocalClose` 合并为 `WsTermination::Closed { code: None }`，随后 `close()` 可返回 `Ok(())`。这条路径没有发送 Close 帧，也没有观察对端确认。窗口在多线程 Tokio runtime 下成立；目前尚无强制该调度顺序的回归测试。

### 对端关闭码的丢失窗口

读任务收到对端 Close 时先把 `Some(code)` 写入 `peer_closed` 通道，再返回 `ReadResult::Closed(code)`。写任务可能在读任务的 `JoinHandle` 被驱动观察前完成 flush。当前“写任务先结束”分支立即中止读任务并固定使用 `ReadResult::LocalClose`，因此可能将已经观察到的对端关闭码记为 `None`。这是由控制信号与终态合并分离造成的另一条调度风险。

实施后必须满足：

1. `WsTermination::Closed { code }` 与 `close() == Ok(())` 只在关闭所需写操作成功且对端 Close 已被观察时成立；不会仅由队列关闭、任务退出或无错误的 `Option::None` 推导成功。
2. 对端 Close 一经读任务观察，成功终态保留其原始 `Option<u16>` 状态码；写操作失败时仍以 `Error { kind }` 为终态。
3. 已有的入队成功语义、单次终态错误交付、显式关闭的期限、取消后重试和最后句柄 Drop 的非阻塞语义不变。业务是否成功继续由应用解释关闭码。

## 方案选择

| 方案 | 优点 | 代价与结论 |
| --- | --- | --- |
| 只交换 `close()` 中两行顺序 | 改动最少 | 不能防止未来其他队列关闭路径再次被解释为成功，也不能保留写任务先结束时的对端码；不采用。 |
| 先发关闭请求，并显式校验写任务退出及对端 Close 快照 | 局部修改即可建立可测试的不变量，沿用当前读写任务和公开终态 API | 需补私有状态合并函数和受控调度测试；采用。 |
| 重写整个驱动为单任务状态机 | 状态集中 | 改动范围和协议回归风险远超本轮缺陷；不采用。 |

## 关闭协调设计

`WsSession::close()` 在持有现有 `close_gate` 后，先发送 `CloseRequest::Local`，再关闭出站应用队列以拒绝新消息并唤醒等待的发送者。两步之间不插入 `await`。这与 `Owner::drop()` 的现有顺序一致。`write_loop` 的 `close.changed()` 分支仍优先于应用队列分支；关闭请求驱动 `sink.close()`、等待对端 Close，并受同一个 `close_timeout` 截止时间约束。

队列 `pop()` 返回 `None` 本身不是协议关闭成功。写任务若在没有已处理关闭请求的情况下观察到出站队列结束，应返回 `WsErrorKind::Internal`，由驱动记录 `Error`；不得通过 `?` 把它折叠成表示成功的 `None`。`watch` 发送失败、任务异常或协议所需写操作失败，也不得生成 `Closed`。不把队列关闭后的所有发送都误报成 `MessageTooLarge`；`WsSendError::Closed` 仍表示停止接纳新消息。

在 `run_parts` 中保留一份只读的 `peer_closed` 观察者。写任务先结束时，从该观察者读取 `Option<Option<u16>>`：

| 写任务结果 | 对端 Close 快照 | 终态 |
| --- | --- | --- |
| 成功 | `Some(code)` | `Closed { code }` |
| 成功 | `None` | `Error { kind: Internal }`，因为没有完成关闭握手的证据 |
| `Some(kind)` | 任意 | `Error { kind }` |

将私有 `resolve_termination` 扩展为同时接收读结果、写结果和对端 Close 快照，供“读任务先结束”和“写任务先结束”两条分支共用；写任务先结束的分支由一个读取快照的私有 helper 封装，便于不依赖线程调度地直接测试。读侧错误优先于后来观察到的写侧错误；写侧失败仍使已观察到的对端 Close 成为 `Error`。读侧为 `LocalClose` 且写侧成功时，只有快照为 `Some(code)` 才生成 `Closed { code }`；快照为 `None` 则为 `Error { kind: Internal }`。只有明确的对端 Close 才能提供公开关闭码。终态仅写一次，之后关闭队列并通知 `receive()`/`close()` 等待者；不扩展公开枚举或添加兼容变体。

## 公共错误接口

为 `WsSendError` 实现 `std::fmt::Display` 和 `std::error::Error`，并按项目风格为错误类型添加 `#[must_use]`。`Display` 只使用固定的、无消息负载和凭据的文字，例如 `WebSocket send queue is full`、`WebSocket session is closed`、`WebSocket message exceeds the outbound limit`。保留 `Backpressure`、`Closed`、`MessageTooLarge` 三个变体及其现有含义；不将它们折叠为 `WsError`。这样返回 `Result<_, Box<dyn Error + Send + Sync>>` 的应用可直接使用 `sender.send(message).await?`。这是向公共类型添加 trait 实现，不需要破坏性 API 变更。

## 测试组织与覆盖

`tests/queue_tests.rs` 当前以 `#[path = "../src/session/queue.rs"]` 重新编译私有队列模块。把四个队列测试及其真正需要私有访问的辅助代码迁入 `src/session/queue.rs` 的 `#[cfg(test)]` 模块，随后移除旧测试文件；公开会话行为仍在 `tests/session_tests.rs` 用 crate 公共 API 验证。迁移时保持断言，不扩大队列可见性，也不新增测试专用公开 API。

关闭回归先写失败测试，再改实现：

- 在私有驱动测试中构造“出站队列已关、关闭请求未发”的受控写任务，断言它不得返回成功；用通道或受控 Sink 固定唤醒顺序，不以循环次数或 `sleep` 代替同步。
- 对写任务先结束的快照读取与终态合并建立表格测试，覆盖 `Some(1000)`、`Some(1009)`、`Some(None)`、未观察到 Close、写失败；调用实际由 `run_parts` 使用的私有 helper，避免只验证孤立公式。另保留 `run_parts` 的受控写失败测试，并用公开会话测试核对对端关闭码。
- 在公开会话测试中确认本地 `close()` 返回 `Ok(())` 前服务端确实收到 Close 并回送确认；保留取消后重试、慢消费者、Ping/Pong、TLS 与 `rs-web` 互通用例。
- 为 `WsSendError` 增加 `Display` 固定文本、标准错误 trait 可通过 `?` 转换、无负载泄漏的测试。
